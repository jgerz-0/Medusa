# CVE Enrichment Job Contract

The CVE enrichment worker attaches deterministic vulnerability intelligence to
existing findings. The controller exposes a `/enrich` endpoint that enqueues
jobs for the worker, and the worker responds with normalized advisory
documents sourced from NVD and CIRCL.

## Controller → Worker Job Payload

The controller serializes enrichment jobs according to the schema below. The
payload is enqueued on `MEDUSA_CVE_ENRICHMENT_QUEUE_CHANNEL` (defaults to
`queues:enrichment:cve`). All timestamps are UTC ISO-8601 strings.

| Field          | Type      | Required | Description |
| -------------- | --------- | -------- | ----------- |
| `job_id`       | string    | ✅       | UUID generated by the controller for traceability. |
| `finding_id`   | string    | ✅       | Identifier of the finding to enrich. |
| `scan_id`      | string    | ✅       | Scan identifier associated with the finding. |
| `cve_id`       | string    | ❌       | CVE identifier reported by the scanner (uppercase). |
| `title`        | string    | ✅       | Human-readable finding title. |
| `severity`     | string    | ✅       | Scanner-reported severity (critical/high/medium/low/info). |
| `metadata`     | object    | ✅       | Deterministic metadata emitted by the scanner (CPEs, template IDs, etc.). |
| `sources`      | array     | ✅       | Ordered list of advisory feeds to query (`["nvd", "circl"]` by default). |
| `requested_by` | string    | ✅       | Principal requesting enrichment. |
| `requested_at` | string    | ✅       | Timestamp when the job was queued (`YYYY-MM-DDThh:mm:ssZ`). |

### Example Job

```json
{
  "job_id": "1d94f2f6-93c8-4a6b-b0f8-1af32d5c994f",
  "finding_id": "0b0a0a60-14de-4f8c-8c7a-367c7751e8fd",
  "scan_id": "4c2b6ce2-b6a4-4d64-9b92-2932fb5d0a27",
  "cve_id": "CVE-2023-2000",
  "title": "Example Finding",
  "severity": "high",
  "metadata": {
    "cpe": ["cpe:/a:vendor:product:1.0"],
    "template_id": "cves/2023/CVE-2023-2000.yaml"
  },
  "sources": ["nvd", "circl"],
  "requested_by": "svc-analyst",
  "requested_at": "2024-01-10T12:00:00Z"
}
```

## Worker → Controller Response Skeleton

The worker posts deterministic enrichment results back to a future controller
callback endpoint. The structure matches the `CVEEnrichmentResult` model.

| Field         | Type      | Description |
| ------------- | --------- | ----------- |
| `job_id`      | string    | Echoes the job identifier supplied by the controller. |
| `finding_id`  | string    | Finding identifier the metadata applies to. |
| `advisories`  | array     | List of normalized advisory documents. |
| `errors`      | object    | Map of advisory sources that failed (e.g., `{ "circl": "timeout" }`). |
| `generated_at`| string    | UTC timestamp when enrichment finished. |

Each advisory entry contains:

| Field        | Type      | Description |
| ------------ | --------- | ----------- |
| `source`     | string    | `nvd` or `circl`. |
| `identifier` | string    | CVE identifier confirmed by the source. |
| `summary`    | string    | Source-provided summary text. |
| `severity`   | string    | Highest severity exposed by the source (uppercase). |
| `cvss_score` | number    | Deterministic CVSS score when available. |
| `published`  | string    | UTC timestamp the advisory was published (if supplied). |
| `modified`   | string    | UTC timestamp the advisory was last modified (if supplied). |
| `references` | array     | Sorted list of reference URLs. |
| `raw`        | object    | Source payload with keys sorted for hashing/auditability. |

### Example Result Payload

```json
{
  "job_id": "1d94f2f6-93c8-4a6b-b0f8-1af32d5c994f",
  "finding_id": "0b0a0a60-14de-4f8c-8c7a-367c7751e8fd",
  "advisories": [
    {
      "source": "nvd",
      "identifier": "CVE-2023-2000",
      "summary": "Example summary from NVD",
      "severity": "CRITICAL",
      "cvss_score": 9.8,
      "published": "2023-05-01T12:30:00+00:00",
      "modified": "2023-05-05T03:12:00+00:00",
      "references": [
        "https://nvd.nist.gov/vuln/detail/CVE-2023-2000",
        "https://vendor.example.com/advisory"
      ],
      "raw": {"...": "normalized advisory document"}
    }
  ],
  "errors": {},
  "generated_at": "2024-01-10T12:00:05+00:00"
}
```

## Security + Determinism Notes

- The worker enforces a pinned User-Agent (`Medusa-CVE-Enrichment/0.1`) when
  fetching advisories to aid in audit log correlation.
- Advisory responses are normalized with sorted keys before hashing so repeated
  runs over the same CVE produce identical payloads.
- If the controller queues a job without a `cve_id`, the worker records a
  deterministic error for each requested source and avoids speculative lookups.
- The enrichment queue channel is separate from scan queues to allow isolated
  scaling policies in Kubernetes and clearer audit events in the controller.
